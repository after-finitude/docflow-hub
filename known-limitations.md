# Известные ограничения

Раздел из состава поставки (ТЗ §16). Пополняется по мере реализации этапов.

## Тулинг TypeScript 7

TypeScript 7 — нативный порт компилятора. Программный API, на который
опирались инструменты эпохи TS 5–6, у него отсутствует. ТЗ этот риск
предвидело и разрешило пакет совместимости; фактическая картина на 2026-08-02:

| Инструмент       | Состояние                                                                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| typescript-eslint | Не поддерживает TS 7: peer-диапазон `>=4.8.4 <6.1.0`. Пакета `tsc6` из ТЗ в реестре npm не существует. Вместо ESLint используется **oxlint** — линтер, не зависящий от компилятора TS. Возврат к typescript-eslint возможен, когда появится совместимый релиз |
| Next.js 16.2      | Не ограничение, а штатный режим: `experimental.useTypeScriptCli` в `apps/web/next.config.ts` — единственный документированный способ работать с TS 7 (страница «Using TypeScript 7»). Next не включает его сам и без него прерывает сборку с инструкцией. Вместо загрузки JS API запускается CLI `tsc`, то есть тот же компилятор, что и у остального монорепозитория. Проверено подстановкой заведомой ошибки типа: сборка падает, значит проверка реально выполняется. Слово experimental относится к возможной смене имени опции |
| `moduleResolution` | Значение `node10` удалено из TS 7. Проект использует `node16`                                                                                     |
| Ambient-дополнения типов | TS 7 не подхватывает глобальные дополнения из пакетов `@types`, которые не импортируются кодом напрямую. Конкретно `Express.Multer.File` из `@types/multer` не виден ни через автоматическое подключение, ни через `/// <reference types>`, ни через пустой type-import. Тип загружаемого файла объявлен явно в `apps/api/src/documents/uploaded-document.ts` |

Динамический `import()` в TS 7 при сборке в CommonJS сохраняется как настоящий
динамический импорт и не превращается в `require` — это позволяет использовать
ESM-пакеты из backend напрямую (проверено на `mupdf`).

Линтинг с учётом типов (type-aware) сейчас не подключён: oxlint выполняет
синтаксические и семантические правила без информации о типах. Роль проверки
типов выполняет `npm run typecheck`.

## Аутентификация

- **Выход не отзывает токен.** В payload нет `jti`, чёрного списка нет: после
  нажатия «Выйти» cookie удаляется, но перехваченный ранее токен остаётся
  действительным до `exp` (по умолчанию 8 часов). Отзыв сессий — отдельная
  задача, в обязательный объём ТЗ не входит.
- **Ограничение частоты попыток входа считается по логину, а не по адресу.**
  Rewrite Next.js не проставляет `X-Forwarded-For` (прокси создаётся без опции
  `xfwd`), поэтому адресом клиента для API всегда оказывается контейнер `web`,
  а доверять заголовку от браузера нельзя — он подделывается тривиально.
  Лимит по логину не обходится подстановкой чужого значения, но позволяет
  занять квоту конкретной учётной записи. Полноценный лимит по адресу появится
  только с обратным прокси перед `web`, который перезаписывает `X-Forwarded-For`.
- **Колонка `audit_events.ip` для запросов через веб-приложение содержит адрес
  контейнера `web`**, а не клиента — по той же причине. Значение станет
  осмысленным с появлением обратного прокси.
- **Ограничение частоты хранится в памяти процесса.** При нескольких
  экземплярах API лимит действует на каждый отдельно. Общий счётчик потребует
  хранилища в Redis.
- **Роль перечитывается из БД на каждый запрос.** Это устраняет работу по
  устаревшему снимку прав, но добавляет один запрос к БД на обращение.

## Обработка документов

- **После OCR документ переходит в `needs_review`.** Это временный терминал
  pipeline: этапы 4–5 вставят классификацию, извлечение и валидацию перед этим
  переходом. Review Workspace появится на этапе 6.
- **`GoogleVisionOcrProvider` не прогонялся против реального сервиса** — код
  написан по типам SDK 5.3.7, ключа service account в разработке нет. Первый
  реальный прогон — на этапе 8 (evaluation). До этого рабочий провайдер — mock.
- **Mock-OCR не распознаёт изображения**: у JPEG/PNG нет текстового слоя,
  возвращается пустая страница с реальными размерами. Полный путь для сканов
  работает только через GCV.
- **Mock-LLM заточен под формат демо-набора**: классификация — заголовочные
  паттерны, извлечение — шаблон «Метка: значение» и только для invoice;
  остальные типы получают честный Missing по всем полям. Line items mock не
  извлекает (возвращает признак отсутствия — это допустимо по ТЗ §13).
- **`OpenAiCompatibleLlmProvider` не прогонялся против реального API** (ключа
  нет). Работа DeepSeek с `response_format: json_object` и качество
  извлечения на русском не проверены; первый прогон — этап 8. Repair-политика
  и zod-валидация подстраховывают формат ответа.
- **`GoogleSheetsAdapter` не прогонялся против реального API** — ключа service
  account в разработке нет, код написан по типам `@googleapis/sheets` 14.
  Проверяется файловый адаптер; Sheets — первый реальный прогон на этапе 8.
- **Маппинг полей на назначения задаётся константой в коде**
  (`packages/core/src/export/mappings.ts`), а не через API. ТЗ допускает
  настройку «через конфигурацию и API»; сейчас реализована только
  конфигурация — через API меняются лишь пороги.
- **Экспорт синхронный**: HTTP-запрос ждёт ответа системы назначения.
  Для Google Sheets это несколько секунд; при пакетной выгрузке понадобится
  очередь `export`, которая уже зарегистрирована.
- **Просмотрщик показывает растровые страницы, а не PDF**: текст в нём нельзя
  выделить и найти поиском. Страницы рендерит сервер (mupdf) при каждом
  запросе — кэш только браузерный (10 минут). При большом числе одновременных
  просмотров это заметная нагрузка; при необходимости страницы можно
  предрассчитывать в хранилище.
- **После правки поля область-источник остаётся прежней.** Она указывает,
  откуда значение было извлечено изначально; для исправленного значения это
  уже не доказательство. Поле помечается «исправлено оператором», но подсветка
  сохраняется как навигационная подсказка.
- **Строки line items не сверяются с итоговыми суммами** — по ТЗ §4 такая
  сверка не входит в обязательный объём.
- **Уникальность invoice_number сравнивает нормализованные строки дословно**:
  «ООО Вектор» и «ООО «Вектор»» будут считаться разными поставщиками. Более
  умное сопоставление контрагентов в объём ТЗ не входит.
- **Нормализация ограничена поворотом по EXIF и растяжением контраста**
  (только на пути GCV). Устранение перекоса (deskew) не реализовано: без него
  падает точность bbox на кривых сканах — оценить на eval-наборе этапа 8.
- **Файл загружается в память целиком** (лимит 25 МБ на файл). При большом
  числе одновременных загрузок это заметно по памяти API; переход на потоковую
  запись в хранилище потребует отказа от буфера multer.

## Второй источник, версии и удаление

- **`GoogleDriveSource` не прогонялся против реального API** — ключа service
  account в разработке нет, код написан по типам `@googleapis/drive` 21.
  Проверяется наблюдаемая папка (`SOURCE_PROVIDER=local_folder`), она проходит
  тот же путь синхронизации.
- **Наблюдаемая папка записывается как источник `drive`.** Перечисление
  источников по ТЗ §7 — Upload / Email / Drive, отдельного значения для
  локальной папки в нём нет, а расширять доменное перечисление ради стенда
  избыточно.
- **Папка читается полностью на каждом проходе**, включая чтение файлов ради
  хеша: журнала изменений у файловой системы нет. Для демонстрационного объёма
  это дёшево, для большого каталога понадобится следящий провайдер.
- **`contentHash` из источника сравнивается с sha256 принятого файла.** У Диска
  своя хеш-функция (MD5), поэтому он работает по курсору, а в снимок попадает
  только при первом проходе, когда сравнивать не с чем. Если курсор Диска
  протухнет, следующий проход перекачает папку целиком — приём при этом
  идемпотентен и лишних версий не создаст.
- **Перемещение файла между папками Диска выглядит как удаление.** Наблюдается
  одна папка; файл, ушедший из неё, для системы исчез.
- **Версии связаны только путём источника.** Отдельной ссылки «предыдущая
  версия» нет: цепочка восстанавливается по `source_type + source_path`.
  У загруженных через интерфейс файлов пути источника нет, поэтому версии для
  них не строятся — повторная загрузка того же файла остаётся дубликатом.
  Файл, удалённый в источнике и возвращённый обратно, принимается как новый
  документ с версией 1: прежняя цепочка уже выведена из обращения.
- **Retention удаляет любые неактуальные документы старше срока**, независимо
  от причины: и удалённые в источнике, и вытесненные новой версией. Записи
  журнала (`audit_events`) переживают документ намеренно — таблица неизменяема.
- **Связь дубликата с удаляемым оригиналом снимается.** Если оригинал уходит
  по retention, дубликат остаётся обычным документом без пометки.
- **Ручной повтор доступен не для всех этапов.** Приём не повторяется (это
  означало бы перечитывание источника), экспорт повторяется со страницы
  документа и никогда автоматически (ТЗ 6.10).
- **Записи DLQ не удаляются.** Ротации у них нет; при длительной эксплуатации
  таблицу нужно чистить отдельной задачей.

## Оценка качества

- **Отчёт на mock-провайдерах измеряет конвейер, а не модель.** Mock-LLM знает
  формат меток демо-набора, поэтому извлечение почти идеально по построению.
  Реальные цифры качества требуют `LLM_PROVIDER=openai_compatible` с ключом;
  это же относится к OCR (`OCR_PROVIDER=google`).
- **Скан низкого качества на mock-пути уходит в `unknown`**: у JPEG нет
  текстового слоя, а mock-OCR его не распознаёт. Именно этот документ даёт
  единственную ошибку classification accuracy (97.6% вместо 100%).
- **Harness не задействует БД и очереди.** Он меряет логику обработки, поэтому
  проверки, которым нужна база (уникальность `invoice_number`, связывание
  дубликатов), в отчёте не участвуют — их покрывает `npm run verify`.
- **Median review time не измеряется**: метрика требует телеметрии действий
  оператора, которой в объёме нет.

## Прочее

- Имя роли БД приложения (`docflow_app`) зафиксировано в SQL-миграции и
  init-скрипте кластера; настраивается только пароль.
- `pdfjs-dist` 6 поставляется как ESM-пакет, а backend собирается в CommonJS:
  на этапах 2–3 его нужно подключать динамическим `import()`.
- Образ MinIO в `docker-compose.yml` взят как `latest` — перед продакшеном
  зафиксировать конкретный релиз.
