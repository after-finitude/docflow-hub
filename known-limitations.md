# Известные ограничения

Раздел из состава поставки (ТЗ §16). Пополняется по мере реализации этапов.

## Тулинг TypeScript 7

TypeScript 7 — нативный порт компилятора. Программный API, на который
опирались инструменты эпохи TS 5–6, у него отсутствует. ТЗ этот риск
предвидело и разрешило пакет совместимости; фактическая картина на 2026-08-02:

| Инструмент       | Состояние                                                                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| typescript-eslint | Не поддерживает TS 7: peer-диапазон `>=4.8.4 <6.1.0`. Пакета `tsc6` из ТЗ в реестре npm не существует. Вместо ESLint используется **oxlint** — линтер, не зависящий от компилятора TS. Возврат к typescript-eslint возможен, когда появится совместимый релиз |
| Next.js 16.2      | Не ограничение, а штатный режим: `experimental.useTypeScriptCli` в `apps/web/next.config.ts` — единственный документированный способ работать с TS 7 (страница «Using TypeScript 7»). Next не включает его сам и без него прерывает сборку с инструкцией. Вместо загрузки JS API запускается CLI `tsc`, то есть тот же компилятор, что и у остального монорепозитория. Проверено подстановкой заведомой ошибки типа: сборка падает, значит проверка реально выполняется. Слово experimental относится к возможной смене имени опции |
| `moduleResolution` | Значение `node10` удалено из TS 7. Проект использует `node16`                                                                                     |

Линтинг с учётом типов (type-aware) сейчас не подключён: oxlint выполняет
синтаксические и семантические правила без информации о типах. Роль проверки
типов выполняет `npm run typecheck`.

## Аутентификация

- **Выход не отзывает токен.** В payload нет `jti`, чёрного списка нет: после
  нажатия «Выйти» cookie удаляется, но перехваченный ранее токен остаётся
  действительным до `exp` (по умолчанию 8 часов). Отзыв сессий — отдельная
  задача, в обязательный объём ТЗ не входит.
- **Ограничение частоты попыток входа считается по логину, а не по адресу.**
  Rewrite Next.js не проставляет `X-Forwarded-For` (прокси создаётся без опции
  `xfwd`), поэтому адресом клиента для API всегда оказывается контейнер `web`,
  а доверять заголовку от браузера нельзя — он подделывается тривиально.
  Лимит по логину не обходится подстановкой чужого значения, но позволяет
  занять квоту конкретной учётной записи. Полноценный лимит по адресу появится
  только с обратным прокси перед `web`, который перезаписывает `X-Forwarded-For`.
- **Колонка `audit_events.ip` для запросов через веб-приложение содержит адрес
  контейнера `web`**, а не клиента — по той же причине. Значение станет
  осмысленным с появлением обратного прокси.
- **Ограничение частоты хранится в памяти процесса.** При нескольких
  экземплярах API лимит действует на каждый отдельно. Общий счётчик потребует
  хранилища в Redis.
- **Роль перечитывается из БД на каждый запрос.** Это устраняет работу по
  устаревшему снимку прав, но добавляет один запрос к БД на обращение.

## Прочее

- Имя роли БД приложения (`docflow_app`) зафиксировано в SQL-миграции и
  init-скрипте кластера; настраивается только пароль.
- `pdfjs-dist` 6 поставляется как ESM-пакет, а backend собирается в CommonJS:
  на этапах 2–3 его нужно подключать динамическим `import()`.
- Образ MinIO в `docker-compose.yml` взят как `latest` — перед продакшеном
  зафиксировать конкретный релиз.
