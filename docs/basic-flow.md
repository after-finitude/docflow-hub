# Сценарий тестирования приложения

Основной пользовательский путь Docflow Hub на демо-стенде: вход → загрузка → проверка полей → исправление → подтверждение → JSON-выгрузка. Названия кнопок ниже соответствуют английскому интерфейсу.

## Текущий режим

Проверено 7 сентября 2026 года:

- На стенде включены **mock OCR и mock LLM**. Для основного сценария используйте текстовые PDF из списка ниже. Этот режим не подтверждает качество распознавания сканов реальными моделями.
- Интеграция **OpenRouter** подготовлена: Qwen для OCR, Gemini 2.5 Flash Lite для классификации и извлечения. Она ещё не включена на стенде. После подключения распознанные Qwen страницы будут требовать ручной проверки до проверки качества на реальных документах.
- **Google Drive и Google Sheets временно отключены.** Кнопка Sheets неактивна и подписана `temporarily disabled`; повтор старой выгрузки в Sheets также отключён.
- Доступны загрузка файлов, синхронизация локальной папки и экспорт в JSON. Выбор **Source** в очереди только фильтрует записи, а не подключает источник.

## Вход

1. Откройте [страницу входа демо-стенда](http://82.202.140.221:3300/login).
2. Введите выданные учётные данные и нажмите **Sign in**.
3. После входа должен открыться экран **Queue**.
4. В правом верхнем углу проверьте логин и роль текущего пользователя.

## Тестовые документы

Файлы находятся в репозитории:

| Файл | Назначение |
| --- | --- |
| [sample-invoice.pdf](../scripts/fixtures/sample-invoice.pdf) | Корректный инвойс: Acme GmbH, `DF-1001`, итог `1440.00`. |
| [invoice-sum-mismatch.pdf](../scripts/fixtures/invoice-sum-mismatch.pdf) | Инвойс Globex Ltd, `DF-2002`: `1200 + 240`, но итог `1400.00`. |
| [corrupted.pdf](../scripts/fixtures/corrupted.pdf) | Повреждённый PDF для проверки отказа. |
| [password-protected.pdf](../scripts/fixtures/password-protected.pdf) | Защищённый PDF для дополнительной проверки отказа. |

Если нужный документ уже есть в **Queue**, используйте его текущее состояние. Если его нет, скачайте файл по ссылке выше и загрузите через **Drop files here or click to select**. Кнопки **Load demo data** нет, но обычная загрузка файлов доступна.

Для сценариев B–D нужен исходный, не помеченный как **duplicate** инвойс с ошибкой суммы, который ещё не экспортирован. **Exported** — завершённый результат: его нельзя редактировать, отклонить, заменить или запустить через **Reprocess**. Для нового полного прохода подготовьте новый инвойс с другим содержимым и уникальным номером у этого поставщика. Простое переименование PDF не меняет checksum и не устраняет дубликат. На отдельном чистом тестовом стенде можно использовать исходные файлы повторно.

## Сценарий A: загрузка и очередь документов

1. Откройте **Queue** и при необходимости загрузите тестовые файлы.
2. Проверьте индикатор **Live updates**. При недоступности SSE допускается **Polling for updates**: очередь обновляется каждые 5 секунд.
3. Проследите статусы **Received** → **Processing** и текущий этап под статусом. На маленьком PDF эти состояния могут пройти слишком быстро, чтобы увидеть каждый; история останется в **Log**.
4. Проверьте столбцы **Type**, **Status**, **Confidence** и **Issues**.
5. Включите **blocking issues only**: должны остаться документы с блокирующими ошибками, включая инвойс с неверной суммой.
6. Нажмите **Reset** и проверьте фильтры **Status**, **Type**, **Source** и диапазон дат.

Ожидаемые результаты при первом проходе без конфликтующих документов и с исходными схемами:

| Документ | Ожидаемый статус |
| --- | --- |
| `sample-invoice.pdf` | Автоматический **Approved**. |
| `invoice-sum-mismatch.pdf` | **Needs review** с блокирующей ошибкой суммы. |
| `corrupted.pdf`, `password-protected.pdf` | **Rejected** с понятной причиной до вызова OCR/LLM. |

Уже существующий инвойс того же поставщика с тем же номером может вызвать дополнительную ошибку уникальности. Повторная загрузка одинаковых байтов создаёт запись с отметкой **duplicate**; она не подходит для повторного сквозного сценария.

## Сценарий B: извлечение полей и связь с оригиналом

1. Откройте неэкспортированный `invoice-sum-mismatch.pdf` со статусом **Needs review**.
2. Убедитесь, что слева отображается оригинал, а справа — извлечённые поля.
3. Выберите фильтр **Validation errors**.
4. Найдите поле **Grand total** и нажмите **Show in document (page 1)**.
5. Убедитесь, что в оригинале подсвечено `Total: 1400.00`.
6. Проверьте confidence, текст ошибки и неактивную кнопку **Approve**.
7. Проверьте масштабирование и поворот страницы: подсветка должна оставаться на том же месте документа.
8. Переключите фильтры **All**, **Missing**, **Low confidence** и **Validation errors**. Для значения без найденного источника показывается **Source not found**, а ссылки на оригинал нет.

Ожидаемый результат: ошибка сообщает, что `1200 + 240 = 1440`, но извлечённый итог равен `1400`.

## Сценарий C: отклонение и повторная обработка

Продолжайте работу с тем же неэкспортированным инвойсом.

1. Нажмите **Reject**, выберите причину и при необходимости добавьте комментарий.
2. Нажмите **Reject document** и убедитесь, что статус стал **Rejected**.
3. Нажмите **Reprocess**.
4. Вернитесь через **Back to queue**, дождитесь **Needs review** и снова откройте документ.

Ожидаемый результат: отклонение сохраняется в истории, а **Reprocess** заново запускает подготовку, OCR, классификацию, извлечение и валидацию. Действие недоступно во время обработки, после экспорта, без сохранённого оригинала и при незавершённой выгрузке.

## Сценарий D: исправление, подтверждение и выгрузка

1. В поле **Grand total** замените `1400` на `1440`.
2. Нажмите **Tab** или щёлкните вне поля: обычные поля сохраняются при потере фокуса. Дождитесь ответа; отдельной кнопки сохранения для них нет.
3. Убедитесь, что ошибка суммы исчезла сразу после сохранения и появилась отметка **Corrected by operator**.
4. Для исправленного `1440` ожидается **Source not found**: оригинал содержит `1400`, поэтому прежняя подсветка больше не считается источником нового значения. Confidence не должен искусственно вырасти до 1.
5. Документ должен остаться в **Needs review**. Если **Approve** недоступна, проверьте оставшиеся blocking-ошибки, например повтор номера инвойса или незаполненное обязательное поле.
6. Нажмите **Approve**. Статус должен стать **Approved**.
7. В разделе **Export** нажмите **Export to JSON file**.
8. Проверьте статус **Exported**, запись `completed` и скачанный `docflow-<document_id>.json`. В JSON поле `fields.grand_total.value` должно содержать `1440`, а `fields.grand_total.edited` — `true`.
9. Нажмите **Download JSON**: должен скачаться уже сохранённый результат без создания новой выгрузки.

Если выгрузка завершилась ошибкой или осталась `pending`, используйте **Retry export** у этой записи. До завершения доставки данные зафиксированы, правки и повторная обработка заблокированы. Если экспорт успешен, но скачивание не удалось, используйте **Download JSON**.

У тестовых инвойсов выше нет таблицы строк; отсутствие `line_items` допустимо. Если проверяете документ со строками, таблица редактируется отдельно через **Add row**, удаление строки и **Save line items** — она не сохраняется по потере фокуса.

## Сценарий E: журнал выполнения

1. Нажмите **Log** в верхней навигации и включите **errors only**.
2. Найдите отказ обработки `corrupted.pdf` и нажмите **Details**.
3. Проверьте **Stage input**, **Result**, **Error message**, число попыток, длительность, код ошибки и `correlation_id`. **Stack trace** отображается, только если он сохранён для задачи.
4. Нажмите **Open document** и проверьте статус **Rejected** с причиной.
5. Отключите **errors only**, выберите этап и проверьте фильтры по датам. После сценария D в журнале должна быть запись этапа **Export**.

Повреждённый PDF не подходит для проверки восстановления после временного сбоя: повтор того же файла не исправляет его содержимое. Для **Retry stage** нужен завершившийся ошибкой этап подходящего, неэкспортированного документа и устранённая причина сбоя. Экспорт повторяется через **Retry export** на документе; для Ingest этот путь повтора этапа недоступен.

**Send to manual review** применяйте к документу, который ещё не получил окончательное решение. Для **Approved**, **Exported** и **Rejected** сервер отклоняет это действие. Подготовка временного сбоя и исчерпание автоматических попыток описаны отдельно в [runbook](runbook.md).

## Сценарий F: дубликат

1. Вернитесь в **Queue** и повторно загрузите те же байты `sample-invoice.pdf`.
2. Найдите новую строку и отметку **duplicate**.
3. Откройте документ и проверьте показанные проблемы. Уникальность номера инвойса может заблокировать уже **Approve**.
4. Дубликат не должен создавать новую выгрузку. Если действие экспорта доступно после ручной проверки, сервер должен отклонить его.

## Итог контрольного прохода

Отметьте результаты после фактической проверки:

- [ ] Queue обновляется, фильтры работают, новые файлы получают статусы.
- [ ] Исходное значение подсвечивается на правильном месте, отсутствие источника обозначено явно.
- [ ] Неверная сумма блокирует подтверждение; исправление снимает эту ошибку сразу.
- [ ] Отклонение и повторная обработка неэкспортированного документа работают.
- [ ] Подтверждение выполняется отдельным действием, JSON содержит исправление и скачивается повторно.
- [ ] Log показывает этапы, отказ невалидного файла и результат экспорта.
- [ ] Повторная загрузка отмечается как duplicate и не создаёт повторную выгрузку.
- [ ] Google Sheets остаётся отключённым.

Этот документ описывает ожидаемое поведение. Его обновление не означает, что заново выполнены все шаги в браузере или закрыта полная приёмка по ТЗ; результаты отдельных проверок находятся в [evaluation](../evaluation/last-run.md).

## Дополнительные проверки

- **Replace file:** нужна новая версия PDF с изменённым содержимым. Кнопка доступна для активной, загруженной через UI версии при разрешённых правках. После замены открывается новый документ, предыдущая версия сохраняется. Уже экспортированный документ заменить нельзя.
- **Смена типа:** **Document type** перезапускает извлечение по выбранной схеме; дождитесь завершения через очередь. Проверяйте на отдельном неэкспортированном документе.
- **Локальная папка:** добавление, изменение и удаление файла выполняются на стороне источника; UI показывает результат синхронизации.
- **Пороги, схемы и настройки:** изменяются через API администратора; отдельного экрана настроек нет.
- **Реальные OCR/LLM:** проверяются после подключения OpenRouter, включая качество русского/английского текста, координаты, скорость и стоимость.
- **Google Drive/Sheets:** отложены до повторного включения интеграций.
- **Retention, аудит и восстановление очередей:** проверяются отдельными автоматическими и интеграционными сценариями.

## Как обрабатывается документ

```text
загрузка на экране Queue
  -> приём и проверка дубликата
  -> проверка файла и подготовка страниц
  -> получение текста и координат
  -> классификация документа
  -> извлечение полей и поиск областей-источников
  -> валидация и расчёт уверенности
  -> автоматическое подтверждение или Review Workspace
  -> JSON-выгрузка
```

При включённом OpenRouter подходящие текстовые страницы PDF разбираются локально через PDF.js, а страницы, которым нужен OCR, передаются Qwen. Классификация и извлечение выполняются Gemini. В текущем mock-режиме внешних AI-вызовов нет.

| Компонент | Роль |
| --- | --- |
| `web` | Queue, Review Workspace, Execution Log и прокси к API. |
| `api` | Вход, загрузка, действия оператора, выгрузка и live-события. |
| `worker` | OCR, классификация, извлечение, валидация, синхронизация и обслуживание. |
| PostgreSQL | Документы, поля, ошибки, запуски этапов, схемы и неизменяемый аудит. |
| Redis / BullMQ | Очереди этапов, повторы, уведомления о статусах и регламентные задачи. |
| MinIO | Оригиналы, миниатюры и сохранённые JSON-выгрузки. |

Подробности находятся в [описании архитектуры](architecture.md), [конфигурации](configuration.md), [runbook](runbook.md) и [known limitations](../known-limitations.md).
